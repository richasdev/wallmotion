# Bounded immutable GIF decoding

This is a second step toward issue #14, following the compositor in PR #142. It does
not replace the application's NSImage GIF renderer, share live players or change the
existing per-view/global admission budgets. FFI, file identity, background scheduling,
cancellation, cache admission, playback clocks and multi-display integration remain.

## Decoder decision

Use pinned `gif = 0.14.2` with only `std` and `raii_no_panic`; the lock resolves
`weezl = 0.1.12`. There is no color quantization dependency. This supplies tested LZW
and interlace handling while our Rust compositor owns rectangle and disposal policy.
The [upstream options](https://docs.rs/gif/0.14.2/gif/struct.DecodeOptions.html) expose
frame consistency and LZW end-code checks, both explicitly enabled here. Unknown block
handling keeps the strict default. Both crates offer MIT OR Apache-2.0 licensing;
the distributed MIT notices are in `resources/ThirdPartyNotices.txt` and copied into
the development app bundle. OSV exact-version queries on 2026-10-30 returned no
advisory IDs for these two versions; this is not a guarantee of absence of defects.

## Contracts

`animation::decode` borrows an immutable encoded slice. Structural preflight checks
encoded length, cumulative full-canvas RGBA estimate and the existing structural work
limit before creating the codec. The frame-count admission precedes codec allocation.
Defaults: 256 MiB encoded, 256 MiB retained RGBA estimate, 384 MiB our working pixel
payload, 10,000 frames. Callers can supply explicit limits.

The returned Animation owns complete straight-RGBA canvases and exposes immutable
slices. It preserves file delays in centiseconds, including zero, and the decoded
repeat value. It has no timing/clamping policy. Raw ICC profile bytes, if present, are
retained separately with an explicit 1 MiB cap for future validation/color conversion;
this module does not transform palette RGB by that profile. Any disposal uses Keep; Background
clears only the previous frame rectangle to transparent RGBA; Previous restores its
saved rectangle. This is an explicit alpha-surface policy, not claimed universal
ImageIO equivalence. Local palettes and deinterlaced indices feed the compositor.

Peak working payload conservatively includes retained output frames, compositor
canvas, pending Previous backup, new Previous backup, indexed frame and the next RGBA
copy. This is checked before new pixel allocations. Fallible reservations are used
for our buffers. The limit excludes the caller's encoded slice, allocator rounding,
frame metadata and third-party codec buffers. It is not an RSS or CPU-time bound.
The conservative peak can reject an image whose final retained estimate alone fits.
A separate codec-buffer limit is canvas pixel count clamped to 1 KiB...64 MiB;
upstream applies it to ancillary XMP/ICC growth as well. Its
[MemoryLimit contract](https://docs.rs/gif/0.14.2/gif/enum.MemoryLimit.html) does not
promise an exact global heap bound. No partially decoded animation is published.

## Verification

Real LZW fixtures generated by the pinned encoder cover local palettes, offset
partial frames, Keep/Background/Previous, raw delays, repeat, interlaced five-row
ordering, every truncated prefix, structurally valid malformed LZW, missing end code,
large XMP on a tiny canvas, exact cumulative working-budget boundaries, and
ICC byte preservation with the inclusive 1 MiB retained-copy limit. Existing
structure/FFI tests remain. Run `sh scripts/check.sh`, then `sh scripts/build-app.sh`;
verify the notice file is bundled and the development signature validates.

No runtime speedup, energy reduction, global memory reduction or physical playback
quality is claimed before integration and measurement.
