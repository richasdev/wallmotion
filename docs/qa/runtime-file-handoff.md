# Isolated real file-handoff QA

Run `python3 scripts/qa-instance-runtime.py --run` on macOS. It archives a committed source SHA (HEAD by default), substitutes only the default library root in that private archive, gives its app a unique `dev.richas.wallmotion.qa.<UUID>` bundle ID/name, generates two 64×64 PNGs and builds an ad-hoc development app. Working-tree edits are excluded from the archive. The existing store-constructor text must match exactly once, and built bundle identity/absence of library/processes are checked before launch. It never spoofs HOME, reads user media/library, enables login items, grants OS permissions, changes power settings or makes network media requests.

The archived app exercises the real AppKit/LaunchServices path with `open`, including forced secondary instances. `open -W -n` waits for the new secondary to exit. The script validates library totals, exact owner PID, one remaining QA process at the expected bundle path, three unique copies with matching generated bytes, and an unchanged temporary JSON after a default no-file reopen. It then stops only apps with that unique QA ID, unregisters the temporary bundle and removes its build/source/library. If an owned QA process fails to terminate, cleanup stops and preserves the checkout rather than deleting a live app. Temporary QA windows may briefly appear; physical UI/focus certification is outside this script.

## Observed sequence

The first isolated run used source `81e187d28d43d031cd54ee2e232fe00e3aef0f64`:

1. Initial no-file launch created one QA owner and no library JSON.
2. Forced secondary with one generated PNG forwarded it, exited, and left the original primary with exactly one managed copy.
3. Forced secondary with two URLs forwarded both and exited; the primary retained three total unique copies with exact fixture bytes. Duplicate source selections intentionally create separate library entries.
4. After graceful QA-primary termination, cold launch with a PNG acquired a new owner PID and imported once (four total entries).
5. A forced default secondary with no URLs exited after activating the existing owner; the temporary library JSON stayed byte-identical.

The application's existing scalar OSLog messages, queried with `log show --info` restricted to the unique temporary process image path, recorded secondary `default=false pending=1/2`, busy admission without model construction, equal expected/returned owner PIDs for activation/forward, and acknowledged exit. Cold URL launch also reported `default=false pending=1`; default no-file launch reported true. No raw file URL is logged by that instrumentation. Saved local scalar evidence: `/tmp/wallmotion-runtime-qa-evidence.json`; the experimental archive/app was stopped and removed.

This demonstrates the observed file handoff cases, not a general exactly-once guarantee or OS restoration/services-without-URL certification. Dispatch acknowledgement still is not an import transaction receipt. The intentionally waiting nondefault/no-URL UI and the earlier unexplained duplicate-process observation remain open under #88; no timer or unsafe PID-only shortcut is added.

Apple sources: [launchIsDefaultUserInfoKey](https://developer.apple.com/documentation/appkit/nsapplication/launchisdefaultuserinfokey) distinguishes file/service/restoration launches; [NSWorkspace.OpenConfiguration](https://developer.apple.com/documentation/appkit/nsworkspace/openconfiguration) specifies launch/open behavior. The QA script uses the production launch path and does not invent a restoration flag.

The reusable opt-in script subsequently passed the same four cases against main source `d12437f8beaaedc413f6928624ca0fa2c85e46e5`, including the HLS preference changes. Its temporary instances and generated build/library were cleaned automatically. This result covers real dispatch/import behavior under that run, without closing the remaining restoration QA.
